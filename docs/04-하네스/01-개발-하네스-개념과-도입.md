# 개발 하네스 개념과 도입

## 하네스란?

하네스는 원래 장비나 대상을 안전하게 고정하고 연결하는 장치를 뜻합니다. AI 주도 개발에서 개발 하네스는 에이전트가 무작정 코드를 바꾸지 않도록 작업 범위, 실행 방법, 검증 방법, 기록 방법을 묶어둔 운영 환경을 의미합니다.

쉽게 말해, 하네스는 “AI 에이전트가 안전하게 일하는 울타리”입니다.

## 왜 필요한가?

AI 에이전트는 빠르게 많은 변경을 만들 수 있습니다. 하지만 기준이 없으면 다음 문제가 생깁니다.

- 작업 범위가 커짐
- 요청하지 않은 파일을 수정함
- 테스트 없이 PR을 만듦
- 문서와 코드가 어긋남
- 실패 원인을 남기지 않음
- 다음 에이전트가 맥락을 잃음

하네스는 이런 문제를 줄이기 위해 필요합니다.

## PDForge 하네스 구성 요소

| 구성 요소 | 설명 | 현재 상태 |
| --- | --- | --- |
| 문서 구조 | 에이전트가 참고할 기준 문서 | 초안 작성 |
| Issue 템플릿 | 작업 지시서 형식 | 초안 작성 |
| PR 템플릿 | 검토 기준 형식 | 초안 작성 |
| Copilot 지침 | 저장소 전체 AI 작업 규칙 | 초안 작성 |
| 테스트 명령 | 코드 변경 검증 방법 | 제품 스택 결정 후 작성 |
| 린터 명령 | 코드 스타일 검증 방법 | 제품 스택 결정 후 작성 |
| 로컬 실행 방법 | 개발 서버 실행 방법 | 제품 스택 결정 후 작성 |
| 회고 템플릿 | 작업 후 학습 기록 | 초안 작성 |

## 도입 순서

### 1단계: 문서 하네스

- 문서 폴더 구조 만들기
- 한글 작성 원칙 정하기
- 회고 작성 원칙 정하기

### 2단계: GitHub 하네스

- Issue 템플릿 추가
- PR 템플릿 추가
- 브랜치 대상 `dev` 고정
- Copilot 저장소 지침 추가

### 3단계: 개발 하네스

제품 기술 스택이 결정되면 다음을 추가합니다.

- 설치 명령
- 개발 서버 실행 명령
- 테스트 명령
- 린터 명령
- 빌드 명령
- 스크린샷 확인 절차

### 4단계: 에이전트 하네스

- custom agent 프로필 작성
- 에이전트별 담당 범위 정의
- handoff 규칙 정의
- 실패 시 되돌리는 기준 작성

## 에이전트에게 제공할 작업 패킷

에이전트에게 일을 맡길 때는 다음 정보를 한 묶음으로 제공합니다.

```md
## 목표

무엇을 끝내야 하는지 적습니다.

## 참고 문서

읽어야 할 docs 문서 링크를 적습니다.

## 변경 가능 범위

수정해도 되는 폴더와 파일을 적습니다.

## 변경 금지 범위

건드리면 안 되는 파일을 적습니다.

## 완료 조건

문서, 코드, 테스트, 회고 기준을 적습니다.

## PR 규칙

PR 제목과 본문을 한글로 작성하고 대상 브랜치를 dev로 지정합니다.
```

## 준비 완료 후 첫 실습 추천

첫 실습은 제품 코드가 아니라 문서 또는 작은 UI로 시작하는 것이 좋습니다.

추천 순서:

1. pdfrend 문서 분석 문서 작성
2. PDForge 서비스 요건 초안 작성
3. PDF 뷰어 첫 화면 와이어프레임 작성
4. 정적 화면 구현
5. 테스트/린터 하네스 추가
6. Copilot custom agent 초안 작성
