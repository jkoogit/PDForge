# PDForge 문서 홈

이 문서는 PDForge를 AI 주도 방식으로 개발하기 전에 필요한 준비 과정을 정리한 문서 허브입니다.

## 문서 운영 원칙

- 문서 제목과 GitHub Issue/PR 제목은 한글로 작성합니다.
- PR 대상 브랜치는 항상 `dev`입니다.
- `stg`, `main`으로 직접 PR을 만들지 않습니다.
- 실제 구현 전에 정책, 요구사항, 설계, 하네스, 회고를 먼저 남깁니다.
- 문서 작업에는 테스트/린터를 실행하지 않습니다.
- 코드 변경이 포함되는 작업에서만 테스트와 린터를 실행합니다.

## pdfrend 문서 분석 상태

리뷰 코멘트에 따라 [pdfrend `dev` 브랜치의 `docs` 문서](https://github.com/jkoogit/PDFrend/tree/dev/docs)를 참고해 1차 분석을 진행했습니다.

분석 결과는 다음 문서에 정리했습니다.

- [`02-기획/02-pdfrend-문서-분석.md`](02-기획/02-pdfrend-문서-분석.md)
- [`02-기획/03-pdforge-서비스-요건-초안.md`](02-기획/03-pdforge-서비스-요건-초안.md)
- [`05-회고/2026-05-29-pdfrend-문서-분석-회고.md`](05-회고/2026-05-29-pdfrend-문서-분석-회고.md)
- [`05-회고/2026-05-30-리뷰댓글-보완-회고.md`](05-회고/2026-05-30-리뷰댓글-보완-회고.md)
- [`05-회고/2026-05-30-issue-pr-작성정리-회고.md`](05-회고/2026-05-30-issue-pr-작성정리-회고.md)
- [`05-회고/2026-05-30-문서정책-일정관리-회고.md`](05-회고/2026-05-30-문서정책-일정관리-회고.md)

현재 판단은 다음과 같습니다.

1. pdfrend의 문서 관리 구조는 PDForge에도 참고합니다.
2. pdfrend의 OCR, 실시간 동기화, 공유 권한, 버전 머지를 그대로 복제하지 않고 PDForge MVP에 필요한 범위로 나눕니다.
3. PDForge 첫 버전은 사용자가 업무 문서, 도서, 스캔 PDF를 업로드하고 OCR·목록·주석 작업을 할 수 있는 웹앱 MVP로 조정합니다.
4. React 기반 웹앱, PDF 라이브러리 내부 래핑, 서버 저장 구조를 문서로 확정한 뒤 구현을 시작합니다.
