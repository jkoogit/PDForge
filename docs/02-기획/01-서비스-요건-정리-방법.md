# 서비스 요건 정리 방법

## 문서 ID

- 기획 ID: `PLAN-REQ-001`
- 관련 작업 ID: `TASK-MVP-001`

## 목적

pdfrend 문서를 참고하되 PDForge를 독립 제품으로 만들기 위해 서비스 관점 요건만 추출하는 방법을 정의합니다.

## 서비스 관점이란?

서비스 관점은 내부 구현보다 사용자 가치와 사용 흐름을 우선하는 관점입니다.

예를 들어 다음처럼 바꿔 씁니다.

| 내부 구현 중심 표현 | 서비스 관점 표현 |
| --- | --- |
| PDF 렌더러 라이브러리를 붙인다 | 사용자는 브라우저에서 PDF를 열어 읽을 수 있다 |
| 페이지 캐시를 만든다 | 사용자는 다음 페이지로 이동할 때 지연을 덜 느낀다 |
| 주석 데이터를 DB에 저장한다 | 사용자는 문서에 남긴 메모를 다시 확인할 수 있다 |

## pdfrend 문서 분석 절차

1. 문서 목록 수집
   - pdfrend의 docs 폴더 구조를 확인합니다.
   - 주제별 폴더와 파일명을 목록화합니다.

2. 문장 분류
   - 사용자 가치
   - 기능 요건
   - 비기능 요건
   - 내부 구현
   - 운영 정책
   - 보류/아이디어

3. PDForge 반영 여부 판단
   - 유지
   - 변경하여 유지
   - 보류
   - 제외

4. 요건 표 작성

```md
| ID | 요건 | 사용자 가치 | 우선순위 | 반영 여부 | 근거 문서 |
| --- | --- | --- | --- | --- | --- |
| REQ-001 | 사용자는 PDF 파일을 열 수 있다 | 문서를 읽기 시작할 수 있다 | 높음 | 유지 | pdfrend 문서 링크 |
```

5. 확정 문서 반영
   - `02-기획`에는 서비스 요건을 정리합니다.
   - `03-설계`에는 요건을 구현하기 위한 구조를 정리합니다.
   - `04-하네스`에는 검증 방법을 정리합니다.
   - `05-회고`에는 분석 과정의 판단과 어려움을 남깁니다.

## 첫 버전 검토 질문과 현재 답변

댓글 검토 결과, 첫 버전 질문은 번호로 관리하고 답변도 같은 번호로 추적합니다. MVP 우선 구현 대상은 아래 답변을 기준으로 조정할 수 있습니다.

| 번호 | 질문 | 현재 답변 | MVP 반영 방향 |
| --- | --- | --- | --- |
| 1 | 사용자는 어떤 상황에서 PDF 뷰어가 필요한가? | 업무 문서, 도서, 스캔 문서를 웹에서 열고 OCR, 목록, 주석 작업을 할 때 필요합니다. | 업무/학습용 PDF 작업 뷰어로 정의합니다. |
| 2 | 작업 파일은 어디에서 가져오는가? | 사용자가 직접 업로드한 PDF 파일을 수집합니다. | 업로드 흐름을 MVP 핵심 진입점으로 둡니다. |
| 3 | 사용자는 읽기만 하는가, 작업도 하는가? | 업로드한 문서에 페이지별 OCR, 목록 작업, 주석 작업을 할 수 있어야 합니다. | 단순 읽기 전용이 아니라 작업 가능한 뷰어로 정의합니다. |
| 4 | 로그인 없이 쓸 수 있는가? | 공유 권한이 있는 문서는 로그인 없이 조회할 수 있고, 작업은 로그인 상태에서만 가능합니다. | 조회 권한과 작업 권한을 분리합니다. |
| 5 | 문서를 서버에 저장하는가, 브라우저 안에서만 처리하는가? | 브라우저에서 작성한 내용을 실시간으로 서버에 반영해야 합니다. | 서버 저장과 동기화 API를 MVP 기반 요건으로 검토합니다. |
| 6 | 모바일을 첫 버전에 포함하는가? | 모바일은 추후 계획입니다. 우선 웹앱 기능을 제공합니다. | 반응형 최소 대응만 검토하고 모바일 최적화는 보류합니다. |
| 7 | 보안상 업로드된 PDF를 어떻게 다루어야 하는가? | 문서 암호화는 이번 범위의 대상이 아닙니다. 다만 암호화 외 접근 제어, 업로드 제한, 권한 검증, 민감정보 노출 같은 보안 검토가 필요합니다. | 암호화는 제외하되 기본 보안 체크리스트를 별도 문서로 작성합니다. |
