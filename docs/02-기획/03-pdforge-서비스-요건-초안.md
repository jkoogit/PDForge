# PDForge 서비스 요건 초안

## 문서 ID

- 기획 ID: `PLAN-MVP-001`
- 관련 작업 ID: `TASK-MVP-001`

## 목적

이 문서는 pdfrend `docs` 문서 분석 결과와 리뷰 코멘트 답변을 바탕으로 PDForge의 첫 제품 방향과 MVP 후보 요건을 정리합니다.

PDForge는 pdfrend를 복제하지 않습니다. pdfrend가 지향하는 “스마트 PDF 작업 및 동기화 플랫폼”에서 서비스 가치와 작업 흐름을 참고하고, PDForge는 독립 제품으로 필요한 범위를 단계적으로 구현합니다.

## 제품 한 줄 정의

PDForge는 사용자가 업무 문서, 도서, 스캔 PDF를 웹앱에서 업로드하고, 페이지별 OCR·목록·주석 작업을 수행한 뒤 서버에 작업 결과를 이어서 저장할 수 있게 돕는 PDF 작업 뷰어입니다.

## 해결하려는 문제

| 문제 | 설명 | 첫 버전 반영 여부 |
| --- | --- | --- |
| PDF를 빠르게 열어 보고 싶다 | 별도 앱 설치 없이 브라우저에서 문서를 확인하고 싶다 | 반영 |
| 업무 문서와 도서 스캔 문서를 작업하고 싶다 | 단순 열람이 아니라 OCR, 목록, 주석이 필요하다 | 반영 |
| 작업 파일을 한 곳에 모으고 싶다 | 사용자가 업로드한 PDF를 기준으로 작업을 시작한다 | 반영 |
| 작업 내용을 잃지 않고 저장하고 싶다 | 브라우저에서 작성한 OCR/목록/주석 결과가 서버에 반영되어야 한다 | 반영 |
| 권한이 있는 사람에게 문서를 보여주고 싶다 | 공유 권한이 있으면 로그인 없이 조회할 수 있어야 한다 | 후보 |
| 작업 권한은 통제하고 싶다 | OCR, 목록, 주석 같은 작업은 로그인 상태에서만 가능해야 한다 | 반영 후보 |
| 모바일에서도 쓰고 싶다 | 모바일 최적화는 필요하지만 첫 범위는 아니다 | 보류 |
| AI 기능을 바로 넣고 싶다 | 개발 방식은 AI 주도지만 제품 기능으로서 AI는 MVP 이후 검토한다 | 보류 |

## 대상 사용자 초안

### 1차 사용자

- 업무 문서를 PDF로 받고 웹에서 확인·정리해야 하는 사용자
- 도서 또는 스캔 PDF를 업로드해 페이지별 OCR과 목록 작업을 하고 싶은 사용자
- PDF 위에 주석과 메모를 남기고 작업 결과를 서버에 보존하고 싶은 사용자
- AI 에이전트 개발 학습 과정에서 실제 제품을 조금씩 만들어 보고 싶은 개발자/학습자

### 아직 1차 사용자가 아닌 대상

- 모바일 앱 수준의 최적화가 먼저 필요한 사용자
- 실시간 공동 편집과 충돌 해결이 필수인 대규모 협업 팀
- 문서 자체 암호화가 필수인 보안 등급의 문서를 다루는 조직
- PDF 편집기 수준의 페이지 삽입, 삭제, 재정렬이 필요한 사용자

## 검토 질문별 결정 사항

| 번호 | 질문 | 현재 결정 | 후속 검토 |
| --- | --- | --- | --- |
| 1 | 사용 상황 | 업무 문서, 도서, 스캔 문서 작업에 필요 | 대표 사용자 시나리오 작성 |
| 2 | 파일 수집 | 사용자가 업로드한 파일로 시작 | 업로드 용량/형식 제한 필요 |
| 3 | 작업 범위 | 페이지별 OCR, 목록 작업, 주석 작업 가능 | MVP에서 OCR 깊이 조정 가능 |
| 4 | 로그인/조회 | 공유 권한 문서는 로그인 없이 조회 가능, 작업은 로그인 필요 | 공개 링크/권한 토큰 방식 검토 |
| 5 | 저장 위치 | 브라우저 작업 결과를 실시간으로 서버에 반영 | 자동 저장 주기와 실패 복구 정책 필요 |
| 6 | 모바일 | 추후 계획, 우선 웹앱 기능 제공 | 반응형 최소 기준만 정의 |
| 7 | 보안 | 문서 암호화는 미대상, 암호화 외 보안 검토 필요 | 접근 제어, 업로드 검증, 권한 검증 체크리스트 작성 |

## MVP 범위

### 반드시 포함할 기능

| ID | 기능 | 사용자 행동 | 완료 기준 |
| --- | --- | --- | --- |
| MVP-001 | 샘플 PDF 열기 | 사용자가 저장소에 포함된 샘플 PDF를 연다 | 개발/검증용 샘플 PDF가 화면에 표시된다 |
| MVP-002 | PDF 업로드 | 사용자가 PDF 파일을 업로드한다 | 업로드한 PDF가 작업 문서로 등록된다 |
| MVP-003 | 페이지 탐색 | 사용자가 이전/다음 페이지 또는 페이지 번호로 이동한다 | 현재 페이지와 전체 페이지 수를 알 수 있다 |
| MVP-004 | 확대/축소 | 사용자가 보기 크기를 조절한다 | 확대/축소 후에도 문서가 읽을 수 있게 표시된다 |
| MVP-005 | 서버 저장 기반 | 사용자가 작성한 작업 결과가 서버에 반영된다 | OCR/목록/주석 중 MVP 대상 데이터가 서버에 저장된다 |
| MVP-006 | 기본 레이아웃 | 사용자가 뷰어, 상단바, 사이드바 구조를 이해한다 | 화면 영역이 역할별로 구분된다 |
| MVP-007 | 작업 상태 안내 | 사용자가 업로드/저장/동기화 상태를 알 수 있다 | 파일명, 페이지, 저장 상태가 표시된다 |

### 포함 후보 기능

| ID | 기능 | 포함 이유 | 결정 필요 사항 |
| --- | --- | --- | --- |
| CAND-001 | 페이지별 OCR | 스캔 문서 작업의 핵심 가치 | MVP에서 실제 OCR 엔진까지 포함할지, 결과 입력 구조만 만들지 결정 |
| CAND-002 | 목록 작업 | 도서/긴 문서 탐색에 중요 | PDF outline, 수동 목록, OCR 기반 목록 중 우선순위 결정 |
| CAND-003 | 주석 작업 | 문서 작업 맥락 보존 | PDF 위 주석인지 별도 메모인지 결정 |
| CAND-004 | 공유 조회 | 권한 있는 문서의 로그인 없는 조회 | 공개 링크와 권한 토큰 정책 검토 |
| CAND-005 | 로그인 기반 작업 | 작업 권한 통제 | 인증 방식을 MVP에 포함할지 결정 |
| CAND-006 | 텍스트 검색 | 텍스트 PDF와 OCR 결과 탐색에 유용 | PDF.js 텍스트 레이어와 OCR 결과 검색 범위 결정 |

### 명시적으로 제외할 기능

| 기능 | 제외 이유 | 재검토 시점 |
| --- | --- | --- |
| 모바일 최적화 | 첫 범위는 웹앱 기능 제공 | 웹 MVP 안정화 후 |
| 문서 자체 암호화 | 이번 범위의 보안 대상이 아님 | 보안 정책 단계에서 별도 검토 |
| 실시간 공동 편집 | 서버 반영은 필요하지만 동시 편집 충돌 해결은 범위가 큼 | 협업 버전 기획 시 |
| 브랜치/머지 버전 관리 | 첫 버전에는 과도함 | 다중 사용자 주석 도입 시 |
| 페이지 삽입/삭제/재정렬 | 뷰어가 아니라 편집기 영역 | 별도 제품 확장 검토 시 |
| 표준 PDF 병합 다운로드 | 주석 저장 모델 확정 후 가능 | 주석 MVP 이후 |
| 제품 기능으로서의 AI 자동화 | AI는 개발 방식으로 활용하고 제품 기능은 MVP 이후 검토 | OCR/목차 자동화 고도화 단계 |

## 첫 화면 구조 초안

pdfrend의 대시보드와 작업 뷰어 개념을 참고하되, PDForge 첫 화면은 업로드와 작업 뷰어를 중심으로 시작합니다.

```text
┌────────────────────────────────────────────────────────┐
│ 상단바: PDF 업로드 / 파일명 / 페이지 / 확대축소 / 저장상태 │
├──────────────┬─────────────────────────────────────────┤
│ 사이드바      │ PDF 렌더링 영역                           │
│ - 페이지      │                                         │
│ - 목록 후보   │                                         │
│ - OCR 후보    │                                         │
│ - 주석 후보   │                                         │
└──────────────┴─────────────────────────────────────────┘
```

## 기술 방향 결정 초안

| 질문 | 현재 결정 | 이유 | 추가 검토 |
| --- | --- | --- | --- |
| 프론트엔드 스택 | React 기반 웹앱 | 에이전트가 다루기 쉽고 PDF 뷰어 UI 구성에 적합 | PWA 적용 여부는 별도 검토 |
| PDF 렌더링 | PDF 라이브러리를 내부 래핑하여 사용 | 라이브러리 교체와 테스트를 쉽게 하기 위함 | PDF.js 직접 사용 또는 래퍼 라이브러리 비교 |
| 저장 시작점 | 로컬 저장부터 검토하되 서버 저장을 최종 목표로 둠 | 빠른 개발과 서버 연동 안정성을 단계적으로 확보 | 아래 저장 순서 비교 참고 |
| 서버 필요 여부 | 필요 | PDF 리소스, 이미지, OCR, 주석 DB 관리와 업로드/다운로드 처리가 필요 | API와 데이터 모델 설계 필요 |
| 샘플 PDF | MVP 구현 과정에는 저장소에 둠 | 자동 검증과 화면 확인을 쉽게 하기 위함 | 저작권 문제 없는 샘플만 사용 |
| AI 기능 | MVP 제품 기능에는 포함하지 않음 | AI는 개발 방식으로 활용하고, 제품 AI 기능은 OCR/목차 자동화 단계에서 검토 | MVP 이후 기능 후보로 관리 |

## 저장 순서 검토

| 방식 | 장점 | 단점 | 현재 판단 |
| --- | --- | --- | --- |
| 로컬 먼저 | 빠르게 UI와 작업 흐름을 검증할 수 있고 서버 장애와 무관하게 개발 가능 | 나중에 서버 모델과 맞추며 재작업이 생길 수 있음 | 초기 프로토타입과 임시 저장에 적합 |
| 서버 먼저 | 업로드, OCR, 주석, 권한 모델을 처음부터 실제 구조로 검증 가능 | 초기 개발 속도가 느리고 인증/DB/API 설계가 먼저 필요 | MVP 서비스 구조 확정 후 필요 |
| 로컬 후 서버 동기화 | 빠른 화면 검증과 실제 서비스 저장을 모두 가져갈 수 있음 | 충돌, 실패 재시도, 동기화 상태 관리가 필요 | PDForge 기본 방향으로 검토 |

## 서비스 정책 초안

| 정책 ID | 정책 | 이유 |
| --- | --- | --- |
| PF-POL-001 | 첫 버전은 웹앱 기능을 우선 제공하고 모바일 최적화는 보류한다 | 제품 범위를 통제하기 위함 |
| PF-POL-002 | 작업 파일은 사용자 업로드를 통해 수집한다 | 실제 업무/스캔 문서 작업 흐름과 맞추기 위함 |
| PF-POL-003 | 조회 권한과 작업 권한을 분리한다 | 공유 조회와 로그인 작업을 함께 지원하기 위함 |
| PF-POL-004 | 브라우저에서 작성한 작업 결과는 서버 반영을 목표로 한다 | OCR/목록/주석 데이터를 재사용하기 위함 |
| PF-POL-005 | 문서 암호화는 MVP 범위에서 제외하되 권한/업로드/접근 보안은 검토한다 | 보안 범위를 명확히 하기 위함 |
| PF-POL-006 | 문서와 Issue 없이 에이전트 코딩을 시작하지 않는다 | AI 주도 개발의 작업 범위를 통제하기 위함 |
| PF-POL-007 | 코드 변경 작업은 테스트/린터 기준을 Issue에 먼저 적는다 | 하네스 기반 검증 습관을 만들기 위함 |
