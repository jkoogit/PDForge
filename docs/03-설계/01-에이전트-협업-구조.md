# 에이전트 협업 구조

## 목적

PDForge 개발 과정에서 여러 AI 에이전트가 어떤 역할로 협업할지 정의합니다.

## 기본 구조

```text
사람 Product Owner
  ├─ 기획 에이전트
  ├─ 설계 에이전트
  ├─ 구현 에이전트
  ├─ 검증 에이전트
  └─ 문서/회고 에이전트
```

사람은 최종 의사결정자입니다. 에이전트는 초안 작성자, 실행자, 검토 보조자입니다.

## 역할별 책임

| 역할 | 입력 | 출력 | 완료 조건 |
| --- | --- | --- | --- |
| 기획 에이전트 | pdfrend 문서, 사용자 목표 | 서비스 요건, 우선순위 | 요건이 사용자 가치로 표현됨 |
| 설계 에이전트 | 확정 요건, 기술 제약 | 구조 설계, 대안 비교 | 구현 에이전트가 작업 가능한 수준 |
| 구현 에이전트 | Issue, 설계 문서 | 코드, 테스트, PR | 테스트/린터 통과 또는 실패 사유 설명 |
| 검증 에이전트 | PR, 완료 조건 | 리뷰 코멘트, 위험 목록 | 누락/위험/회귀 가능성 확인 |
| 문서/회고 에이전트 | 작업 결과, 대화 로그 | 문서 업데이트, 회고 | 다음 작업자가 이해 가능 |

## 협업 규칙

1. 한 Issue에는 한 가지 목적만 둡니다.
2. 에이전트에게 맡기기 전에 참고 문서를 명시합니다.
3. 에이전트가 만든 결과는 다른 에이전트나 사람이 검토합니다.
4. 코드와 문서가 충돌하면 문서를 먼저 갱신한 뒤 코드를 수정합니다.
5. 작업 종료 후 회고 문서를 남깁니다.

## 작업 흐름 예시

```text
문서 작성 → Issue 생성 → 기획 에이전트 초안 → 사람 승인 → 설계 에이전트 구조화 → 구현 에이전트 PR → 검증 에이전트 리뷰 → 사람 병합 → 회고
```

## 에이전트 간 handoff 기준

handoff는 한 에이전트의 결과를 다음 에이전트에게 넘기는 단계입니다.

| 이전 역할 | 다음 역할 | 넘겨야 할 정보 |
| --- | --- | --- |
| 기획 | 설계 | 확정 요건, 제외 범위, 우선순위 |
| 설계 | 구현 | 파일 구조, 기술 선택, 테스트 기준 |
| 구현 | 검증 | 변경 파일, 실행 명령, 남은 위험 |
| 검증 | 문서/회고 | 승인/수정 의견, 발견한 문제 |

## 처음 만들면 좋은 에이전트 프로필

처음부터 많은 에이전트를 만들기보다 다음 2개부터 시작합니다.

1. `pdforge-docs-agent`
   - 문서 구조화, 요건 정리, 회고 작성 담당

2. `pdforge-coding-agent`
   - 작은 구현 작업, 테스트 실행, PR 작성 담당

제품 구조가 안정되면 설계/검증 전문 에이전트를 분리합니다.
