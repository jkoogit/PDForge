- 초기에는 pdfrend 문서 경로가 정리되지 않아 분석 절차를 먼저 문서화했습니다.

## 잘된 점

- 실제 코딩 전에 운영 기준을 먼저 정리했습니다.
- 문서/기획/설계/하네스/회고 폴더를 분리해 이후 작업을 주제별로 관리할 수 있게 했습니다.

## 어려웠던 점

- 이후 리뷰 코멘트로 pdfrend `dev` 브랜치의 [`docs`](https://github.com/jkoogit/PDFrend/tree/dev/docs) 경로를 참고할 수 있음을 확인했습니다.
- 제품 기술 스택이 아직 정해지지 않아 테스트/린터/빌드 하네스는 구체 명령까지 작성하지 않았습니다.

## 다음 개선점

- pdfrend `docs` 경로를 계속 참조 문서로 사용하고, 근거 링크를 문서에 남겨야 합니다.

- GitHub Issue를 만들어 Copilot 또는 Codex에게 작은 문서 작업부터 맡기는 실습을 진행해야 합니다.
- React, PDF 라이브러리 내부 래핑, 서버 저장 구조를 정한 뒤 테스트/린터/빌드 명령을 하네스 문서에 추가해야 합니다.
