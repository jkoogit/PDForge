# AI 주도 개발 준비 과정

## 목적

이 문서는 PDForge에서 실제 코딩을 시작하기 전에 AI 주도 개발 방식을 이해하고 준비하기 위한 학습 순서를 정리합니다.

## AI 주도 개발의 핵심 개념

AI 주도 개발은 사람이 모든 코드를 직접 작성하는 방식이 아닙니다. 사람이 문제, 기준, 우선순위, 검토 기준을 정의하고 AI 에이전트가 조사, 초안 작성, 코드 수정, 테스트 보조를 수행하는 방식입니다.

역할을 나누면 다음과 같습니다.

| 역할 | 사람이 담당 | AI 에이전트가 담당 |
| --- | --- | --- |
| 방향 설정 | 제품 목표, 범위, 우선순위 결정 | 대안 정리, 영향 분석 보조 |
| 요구사항 | 최종 요건 승인 | 문서 분석, 초안 작성 |
| 설계 | 구조 선택, 위험 판단 | 설계안 비교, 문서화 |
| 구현 | 리뷰, 승인, 릴리스 판단 | 코드 작성, 테스트 실행, PR 작성 |
| 회고 | 판단과 학습 정리 | 작업 로그 요약, 개선안 제안 |

## 준비 단계 체크리스트

### 1단계: 저장소 운영 기준 만들기

- 브랜치 정책 확정
- Issue/PR 제목 한글 규칙 확정
- 문서 폴더 구조 확정
- 테스트/린터 실행 기준 확정

### 2단계: 서비스 요건 정리 방식 만들기

- pdfrend 문서에서 서비스 관점 요건만 추출하는 기준 만들기
- 내부 구현 설명과 사용자 가치 설명을 분리하는 규칙 만들기
- PDForge에서 유지할 기능과 제외할 기능을 구분하는 표 만들기

### 3단계: 에이전트 협업 구조 설계

- 기획 에이전트
- 설계 에이전트
- 구현 에이전트
- 테스트/검증 에이전트
- 문서/회고 에이전트

각 에이전트가 담당할 입력, 출력, 완료 조건을 문서화합니다.

### 4단계: 개발 하네스 구성 이해

하네스는 에이전트가 안전하게 일하도록 감싸는 운영 장치입니다. 예를 들어 다음을 포함합니다.

- 작업 지시 템플릿
- 테스트 명령
- 린터 명령
- PR 템플릿
- 회고 템플릿
- 로컬 실행 방법
- 에이전트가 접근해야 할 문서 목록

### 5단계: 작은 작업으로 실습

처음부터 제품 전체를 맡기지 않습니다. 다음처럼 작고 검토 가능한 작업부터 시작합니다.

1. 문서 목차 정리
2. 서비스 요건 표 초안 작성
3. 화면 하나의 와이어프레임 작성
4. 정적 UI 하나 구현
5. 테스트 하나 추가
6. 회고 작성

## 준비 완료 판단 기준

다음 질문에 모두 답할 수 있으면 실제 에이전트 코딩을 시작할 수 있습니다.

- PDForge가 해결하려는 사용자 문제가 무엇인가?
- 첫 번째 버전에서 반드시 필요한 기능은 무엇인가?
- Copilot/Codex에게 맡길 첫 번째 Issue는 무엇인가?
- 에이전트가 참고해야 할 문서는 어디에 있는가?
- 결과물을 어떤 기준으로 검토할 것인가?
- 코드 변경 시 어떤 테스트와 린터를 실행할 것인가?
- 실패하거나 방향이 틀렸을 때 어떻게 되돌릴 것인가?

1. pdfrend `dev` 브랜치의 [`docs`](https://github.com/jkoogit/PDFrend/tree/dev/docs)를 계속 참조 문서로 사용합니다.
2. [`docs/02-기획/03-pdforge-서비스-요건-초안.md`](../02-기획/03-pdforge-서비스-요건-초안.md)의 댓글 검토 결과를 바탕으로 MVP 범위를 확정합니다.

6. 구현 Issue를 만들기 전 테스트/린터/빌드 명령을 하네스 문서에 추가합니다.
