# Issue와 PR 작성 가이드

## 문서 ID

- 정책 ID: `POL-ISSUE-001`
- 관련 작업 ID: `TASK-MVP-001`

## 목적

이 문서는 PDForge에서 GitHub Issue와 PR을 함께 관리하는 방법을 정리합니다. 에이전트가 작업할 때 Issue를 작업 지시서로 사용하고, PR을 검토 가능한 결과 보고서로 사용하도록 작성 기준을 맞춥니다.

## 기본 원칙

1. Issue는 “왜, 무엇을, 어디까지” 작업할지 정하는 문서입니다.
2. PR은 “무엇을 바꿨고, 어떻게 확인했으며, 어떤 Issue를 해결하는지” 설명하는 문서입니다.
3. PR 본문 첫 줄에는 작업브랜치명을 표시합니다.
4. PR 본문에는 관련 Issue를 반드시 적습니다.
5. Issue와 PR 제목은 한글로 작성합니다.
6. PR 대상 브랜치는 항상 `dev`입니다.
7. `stg`, `main`으로 직접 PR하지 않습니다.
8. 문서만 변경한 작업은 테스트/린터를 실행하지 않습니다.
9. 코드 변경이 있는 작업은 테스트/린터 실행 결과를 PR에 적습니다.

## Issue 작성 기준

Issue에는 다음 항목을 포함합니다.

| 항목 | 작성 내용 | 예시 |
| --- | --- | --- |
| 배경 | 왜 이 작업이 필요한지 | pdfrend 문서 분석 결과를 PDForge MVP 요건에 반영해야 한다 |
| 목표 | 작업이 끝나면 무엇이 달라지는지 | 서비스 요건 초안에 검토 질문 답변이 반영된다 |
| 참고 문서 | 에이전트가 읽어야 할 문서 | `docs/02-기획/03-pdforge-서비스-요건-초안.md` |
| 완료 조건 | 끝났다고 판단할 기준 | 번호별 질문/답변 표가 추가된다 |
| 제외 범위 | 이번 작업에서 하지 않을 일 | 제품 코드 구현은 하지 않는다 |
| 회고 | 회고 작성 여부 | `docs/05-회고`에 회고 문서를 추가한다 |

## Issue 제목 예시

```text
[문서] 리뷰 댓글 기반 MVP 요건 보완 및 PR 작성 규칙 정리
[기획] PDForge MVP 범위 확정
[설계] PDF 라이브러리 내부 래핑 구조 작성
[하네스] React 기반 개발 명령 정리
[회고] MVP 범위 확정 작업 회고
```

## PR 작성 기준

PR에는 다음 항목을 포함합니다.

| 항목 | 작성 내용 |
| --- | --- |
| 관련 Issue | 연결된 Issue 번호와 제목을 적습니다. 번호가 없으면 “아직 GitHub Issue 미생성”이라고 적습니다. |
| 작업 내용 | 변경한 문서, 정책, 기획, 설계, 코드 내용을 요약합니다. |
| 확인 방법 | 문서 작업은 수동 검토, 코드 작업은 실행한 테스트/린터 명령을 적습니다. |
| 관련 문서 | 근거가 된 docs 문서와 외부 링크를 적습니다. |
| 회고 | 작성하거나 갱신한 회고 문서를 적습니다. |
| 다음 작업 | 이 PR 이후 이어서 할 작업을 적습니다. |

## PR 본문 템플릿

```md
작업브랜치명: `20260530_Codex_이슈제목현행화`

## 관련 Issue

- Closes #이슈번호
- 관련 Issue가 아직 없으면: 아직 GitHub Issue 미생성

## 작업 내용

- 변경한 내용을 한글로 요약합니다.

## 확인 방법

- 문서 변경만 있는 경우: 문서 검토만 수행했습니다.
- 코드 변경이 있는 경우: 실행한 테스트/린터 명령을 적습니다.

## 관련 문서

- 관련된 docs 문서 링크를 적습니다.

## 회고

- 작성한 회고 문서 링크를 적습니다.

## 다음 작업

- 이어서 해야 할 작업을 적습니다.
```

## 이번 초기 문서 PR에 대한 Issue 정리 예시

아직 실제 GitHub Issue 번호가 없는 경우, PR에는 아래처럼 “가상 Issue 요약”을 포함해도 됩니다. 나중에 GitHub Issue를 만들면 번호를 연결합니다.

### Issue 1

```md
제목: [문서] 초기 정책·기획·설계·하네스 문서 및 GitHub 템플릿 추가

배경:
PDForge는 실제 제품 코딩 전에 AI 주도 개발 방식, 에이전트 협업 구조, GitHub 운영 기준을 먼저 정리해야 한다.

목표:
- 문서 홈과 정책, 학습, 기획, 설계, 하네스, 회고 문서를 추가한다.
- GitHub Issue/PR 템플릿과 Copilot 지침을 추가한다.
- pdfrend docs를 참고한 서비스 관점 요건 초안을 정리한다.

완료 조건:
- `docs` 폴더에 주제별 문서가 추가된다.
- `.github`에 Issue/PR 템플릿이 추가된다.
- 문서 작업이므로 테스트/린터는 실행하지 않는다.
- 회고 문서가 추가된다.

제외 범위:
- 제품 코드 구현
- 프론트엔드/백엔드 기술 스택 확정
- 서버 API 구현
```

### Issue 2

```md
제목: [문서] 리뷰 댓글 기반 MVP 요건 보완 및 PR 작성 규칙 정리

배경:
리뷰 댓글에서 첫 버전 검토 질문에 대한 답변이 제공되었고, PR 작성 시 Issue 정보도 포함해야 한다는 요구가 추가되었다.

목표:
- 검토 질문과 답변을 번호로 관리한다.
- React 기반 웹앱, PDF 라이브러리 내부 래핑, 서버 저장, OCR·목록·주석 후보 기능을 문서에 반영한다.
- PR 템플릿과 운영 문서에 관련 Issue 작성 영역을 추가한다.

완료 조건:
- 서비스 요건 초안이 최신 댓글 기준으로 보완된다.
- PR 본문 템플릿에 `관련 Issue` 항목이 포함된다.
- 회고 문서가 추가된다.

제외 범위:
- 실제 GitHub Issue 생성 자동화
- 제품 코드 구현
```

## 에이전트에게 요청할 때 사용할 문장

```text
이 Issue를 기준으로 작업해줘.
PR 제목과 본문은 한글로 작성해줘.
PR 본문 첫 줄에 작업브랜치명을 적어줘.
PR 대상 브랜치는 dev로 해줘.
PR 본문 맨 위에 관련 Issue 번호와 제목을 적어줘.
이번 작업이 문서 작업이면 테스트와 린터는 실행하지 마.
코드 변경이 있으면 테스트와 린터 실행 결과를 PR에 적어줘.
작업 후 docs/05-회고에 회고 문서를 추가해줘.
```
