# 문서화 원칙

## 문서 ID

- 정책 ID: `POL-DOC-001`
- 관련 작업 ID: `TASK-MVP-001`

## 목적

PDForge는 AI 에이전트가 코드를 작성하기 전에 사람이 이해할 수 있는 기준을 먼저 세우는 방식으로 운영합니다. 문서는 에이전트에게 작업 방향을 전달하는 입력 자료이자, 사람이 결정을 추적하는 기록입니다.

## 기본 원칙

1. 한글 우선
   - 문서 제목, Issue 제목, PR 제목, PR 본문은 한글로 작성합니다.
   - 코드 식별자, 파일 확장자, 명령어처럼 기술적으로 필요한 표현은 영어를 허용합니다.

2. 서비스 관점 우선
   - pdfrend의 내부 구현 방식보다 사용자가 경험하는 문제, 가치, 흐름을 먼저 정리합니다.
   - 기능 설명은 “사용자가 무엇을 할 수 있는가”로 작성합니다.

3. 결정과 근거 분리
   - 결정 사항은 짧고 명확하게 씁니다.
   - 근거, 대안, 보류 사유는 별도 문단으로 남깁니다.

4. 작업마다 회고 작성
   - 문서 정리, 정책 변경, 설계 변경, 코드 구현 등 의미 있는 작업마다 회고를 남깁니다.
   - 회고에는 잘된 점, 어려웠던 점, 다음 작업에서 개선할 점을 포함합니다.

5. 문서 작업과 코드 작업 구분
   - 문서만 변경한 경우 테스트/린터를 실행하지 않습니다.
   - 코드 변경이 있는 경우에는 관련 테스트와 린터를 실행합니다.

6. 참조 문서 링크 명시
   - 문서 작성 시 `참조 문서` 또는 `관련 문서` 영역에 근거가 된 문서 링크를 남깁니다.
   - 가능하면 문서 전체 링크가 아니라 해당 내용으로 바로 이동할 수 있는 제목 앵커 또는 GitHub line 링크를 사용합니다.
   - 외부 문서를 참고한 경우 원문 링크와 PDForge에서 해석한 내용을 함께 적어 다음 작업자가 근거와 판단을 구분할 수 있게 합니다.
